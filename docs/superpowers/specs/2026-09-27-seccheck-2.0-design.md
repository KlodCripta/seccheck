# SecCheck 2.0 — approved product direction

Updated 10 October 2026. This replaces the earlier development design.

## Purpose

Run the existing three security checks, then help the user investigate their
warnings automatically. Preserve the simple experience of version 1.0 with more
reliable evidence handling and a single chosen language.

## Workflow

- Choose English or Italian once.
- Check dependencies; show missing tools at startup and offer installation.
- Main menu: complete scan, individual checks, tools, exit.
- Full scan: rkhunter, Lynis, package-file integrity (pacman + pacutils).
- First result: unresolved count and incomplete checks, without logs or file lists.
- Offer analysis, show warnings, or finish. Italian acceptance uses s.
- Analysis uses the existing privileges and supported read-only verifications.
- Final result separates explained items, unresolved items and optional advice.
- Remaining items are filtered and paginated. Other results contains optional
  improvements, explained warnings and short/technical reports.

## Presentation

Cold white dominates, with bold and italic hierarchy. SEC and part of the subtitle
are red; CHECK is white. Red, orange and green communicate priority. No petrolio
or additional accent colours. Keep the enlarged frame and narrow-terminal fallback.

## Evidence and actions

No infection percentages. Optional configuration suggestions cannot create a
malware diagnosis; incomplete coverage cannot be clear. Never approve a file by
its name or clear a strong indicator with an unrelated checksum.

Preserve original logs, stable finding IDs, checks and private report permissions.
Specific explanations must match the actual finding; a purpose explanation does
not prove a modified file legitimate. A report that cannot be read or an unsupported
check remains unresolved. Corrections require a concrete explanation and consent;
this revision retains investigation and advice without automatic system changes.
